# Threats to validity

| Type | Threat | Mitigation |
|---|---|---|
| Internal | Duplicate and near-duplicate flows across partitions inflate scores | exact dedup before split; block split with purging; near-duplicate cross-partition rate reported; sensitivity S7 scores without near-duplicates of fitting/tuning data |
| Internal | Outputs built under older rules or altered after the run | dataset config fingerprint checked at every load; `--verify` checks SHA-256 of all outputs and of every S7 sidecar and record |
| Conclusion | CICIDS2017 test holds few attack-bearing 300 s blocks (17 after S7; whole-test count in `near_duplicates.json`), so its block-bootstrap CI rests on few clusters | reported beside H1a; S7 for H1a and the S7 Δ for H1b/H1c reported as not estimable under the fixed minimum |
| Internal | Identifier shortcuts (IPs, ports, timestamps, flow ids) | removed from features; ports tested only as sensitivity S2 |
| Internal | Preprocessing fitted on test or target data | all learned transforms fitted on source train only, hashed and frozen |
| Internal | Label errors in CIC releases | corrected releases; raw label kept; "Attempted" handled by a fixed rule with sensitivity S3 |
| Internal | Analysis choices made after seeing results | protocol frozen 2026-10-25; amendments log; prior exposure disclosed |
| Construct | Macro-F1 depends on class prevalence, which differs between datasets | per-class recall and balanced accuracy reported beside every Δ |
| Construct | CICFlowMeter and Argus features are not the same quantities | mapping table with exact/approximate/unavailable status; sensitivity S5 |
| Construct | Binary task hides which attacks transfer | multiclass family analysis S6 |
| Conclusion | Correlated flows treated as independent | block bootstrap over 300 s blocks, LANL bootstrap over red-team accounts |
| Conclusion | Many comparisons | confirmatory family with Holm; secondary comparisons labelled as such |
| Conclusion | Training variability not in the CI | 5 seeds; seed spread reported |
| External | Lab benchmarks are not production networks | conclusions limited to the datasets used |
| External | CIC-IoT2023 has no time or host fields, so only a within-file order split is possible | stated as a limitation; not used as a source dataset |
| Construct | Same column name does not guarantee same meaning across CIC releases | both corrected releases use the same fixed CICFlowMeter; shared list frozen; UNSW only through the documented mapping, S5 |
| Construct | The CNN-LSTM's convolution and recurrence run over the fixed column order of one flow's feature vector, which carries no time, so it is not a sequence model of traffic | described as a feature-position baseline in the protocol (§6a) and the paper; candidates are compared as fixed recipes, and no claim rests on its architecture |
| Conclusion | In the `cic` space random forest (val macro-F1 0.999620), XGBoost (0.999754) and the MLP (0.999421) are all within the preregistered tie margin of 0.0005 of the best, so the proposed detector is chosen by candidate order, not by a meaningful validation difference | rule fixed before training (ADR-0007) and applied mechanically; six-decimal tables and the freeze record show the tie; XGBoost and the MLP are reported on every test and target as baselines, with the secondary model comparisons |
| Conclusion | Level 3 validation holds 63 hosts, all first compromised on day 13, so selecting the H2 model and its threshold rests on a small sample, and the best val early-alert rate under the 1.5 rules (0.349, 95 % Wilson 0.243-0.472) is below Y = 0.50; since 1.6 the val false-alarm host-days are those of days 11-12 only | preregistered rule applied unchanged and no re-tuning after seeing validation (the author's decision, 2026-10-26); H2 is decided on the sealed test period with a bootstrap over red-team accounts, and a result below Y is reported as not supported |
| Internal | The Level 3 label rule at the end of a period was corrected (amendment 1.6) after the 1.5 validation results had been seen, and Level 3 was developed and frozen again | the correction follows from the estimand (a row whose 24 h outcome lies after the period end has no known label) and was raised by an external review, not by a result; candidates, grids, selection rule, budget and Y are unchanged; the 1.5 freeze is kept and checked, and both val results are reported, whichever candidate 1.6 selects |
| Construct | 27 of the 44 test hosts are first compromised on day 14, so part of their 24 h alert window lies on day 13, before the test period | under 1.6 those hours belong to no development set; the model scores them like any other hour; a boundary sensitivity counting only alerts on days 14-58 was declared before testing and is reported beside H2 |
| Conclusion | H4 has not been run when H1a-H1c and H2 are decided, but it is in their Holm family | H4 p-values enter as 1; Holm's rejections only grow as p-values fall, so supported and not-supported decisions stand, and inconclusive ones are labelled provisional until Level 4 |
| Conclusion | Neural candidates are scored on a GPU, development scores were computed on the CPU | same preprocessing; the GPU-CPU score difference and the number of differing decisions on 200 000 rows per evaluation set are recorded in every unit |
| Construct | Level 4 flows are labelled by this study, not by the dataset publishers: capture-name labels mark any benign background traffic inside an attack capture as attack (as the released CIC IoT CSVs do), and ToN_IoT labels depend on matching flows to its ground truth | label rules fixed before extraction (§9a); attacking-endpoint sensitivity where the documentation names the attackers; ToN_IoT agreement with the published Zeek labels reported |
| Construct | The re-extracted flows could differ from the source feature space if the extractor version differs | extractor check on a CICIDS2017 capture day with fixed pass criteria before any Level 4 capture is processed (§9a) |
| Conclusion | The CICIoMT2024 capture size was estimated, not measured (the server reports no file sizes) | sizes measured at download and recorded with SHA-256 in the manifest |
